# Science_Metro · Element_Metro

외우기 어려운 과학 지식, 타이핑하며 배워 봐요.

**Science_Metro**는 순서가 있는 과학 지식을 지하철 노선으로 만들고, 역마다 답을 입력하며 종착역까지 달리는 과학 타이핑 게임입니다. 첫 서비스 **Element_Metro**는 주기율표 자체가 노선도예요. 원소 하나가 역 하나입니다.

사이음(sci_eum)이 만듭니다. 현직 과학 교사가 만드는 교실 속 과학 콘텐츠 브랜드예요.

## 무엇을 할 수 있나요

- **노선 16개**: 기본선(1–20번), 전이금속 1·2호선, 전이금속 통합선, 란타넘족선, 악티늄족선, 알칼리 금속선, 할로젠선, 비활성 기체선, 2~7주기선, 그리고 1번부터 118번까지 전부 달리는 **종주선**.
- **모드 6개** (쉬운 순서):

  | 모드 | 보이는 것 → 쓰는 것 |
  |---|---|
  | 연습 | 기호 → 이름 (연하게 깔린 이름을 따라 씀) |
  | 이름 쓰기 | 기호 → 이름 |
  | 기호 쓰기 | 이름 → 기호 |
  | 번호 쓰기 | 원자번호 → 기호 (역 순서가 섞여 나옴) |
  | 혼합 | 이름 ↔ 기호 |
  | 완전 혼합 | 이름 · 기호 · 번호 섞임 |

- **플레이**: 3 · 2 · 1 · 출발! 카운트다운, 1/100초 시계, Enter로 제출, 두 번 틀리면 첫 글자 힌트, '모르겠어요(Esc)'로 넘어가기.
- **원소 이름**: 예전 이름도 정답으로 인정해요(불소 → 플루오린, 크롬 → 크로뮴 등). Na·K는 교과서와 수업에서 익숙한 **나트륨·칼륨**으로 보여 주고, 대한화학회 표기 소듐·포타슘도 정답으로 받아요.
- **결과**: 시간·정확도·평균 타수(타/분, 두벌식 자모 단위), 도장 3개(완주 · 정확도 90% · 무오답), 다시 볼 역, 틀린 역만 다시 달리기, 기록 복사, 인스타 스토리용 결과 카드(1080×1920 PNG).
- **기록**: 노선·모드별 최고 기록은 이 브라우저에만 저장해요. 로그인이 없고 개인정보를 받지 않아요.
- **주기율표 학습** (`/element/table`): 118칸 주기율표, 분류별 보기, 이름·기호 검색. 원소를 누르면 상세 팝업이 열려요 — 큰 기호와 보어 모형, 이름(대한화학회 표기·예전 이름·영어·한자·중국어·기호 유래), 전자 배치와 오비탈 상자, 원자량·밀도·녹는점·끓는점·전기 음성도, 발견 이야기, 그 원소를 지나는 노선. 이름 밖의 값은 아직 교사 검수 전이에요.
- **바로 가는 주소**: `/element/<노선>?mode=<모드>` 예) `/element/full?mode=practice`, 원소 상세 `/element/table?z=11`

## 실행하기

```bash
cd app
npm install
npm run dev        # 개발 서버 http://localhost:5173
npm test           # 판정 함수 단위 테스트
npm run build      # 데이터 검사 → 타입 검사 → 빌드 (dist/)
```

Vite + TypeScript(프레임워크 없음), 테스트는 Vitest. 정적 빌드라 Vercel 등에 그대로 올릴 수 있어요(`app/vercel.json`).

## 새 노선 추가하기

`app/data/lines/<노선id>.json` 파일 하나를 추가하면 노선 선택 화면에 자동으로 나타나요. 화면 코드는 고치지 않습니다.

```json
{
  "id": "halogen",
  "service_id": "element",
  "name": "할로젠선",
  "subtitle": "17족 F–Ts",
  "color": "line-halogen",
  "description": "위 역일수록 반응성이 큼",
  "station_ids": [9, 17, 35, 53, 85, 117],
  "group": "zone",
  "curriculum": ["통합과학", "화학"],
  "level": 1,
  "status": "open",
  "order": 8
}
```

빌드할 때 데이터 검사가 돌아서 없는 역을 참조하거나, 역이 중복되거나, 별칭이 다른 원소 이름과 겹치면 빌드가 실패해요. `status: "draft"`인 노선은 주소 끝에 `?preview=1`을 붙여야 보여요.

## 폴더 구조

```
app/
  data/            원소 118개(stations.json), 노선(lines/*.json), 모드(modes.json), 서비스(services.json)
  src/engine/      게임 엔진: 판정·진행·기록 비교. '원소'를 모르는 일반 로직
  src/map/         Element_Metro 지도 모듈: 주기율표 노선도(SVG)
  src/ui/          화면: 홈, 노선 선택, 플레이·결과, 내 기록, 결과 카드
  tests/           판정 함수 단위 테스트
  scripts/         빌드 때 데이터 검사
docs/              기획·디자인 문서 (아래 표)
scripts/gate.mjs   단계별 통과 검사 (게이트)
rules.json         수치·목록 기준 (표기, 개인정보, 디자인 규칙)
CLAUDE.md          Claude Code 작업 하네스 안내
```

게임 엔진은 원소를 모르게 만들었어요. 엔진이 아는 것은 '역에서 보여 줄 칸', '인정할 정답', '입력 방식', '판정 방식'뿐이고, 원소 관련 내용은 데이터와 지도 모듈에만 있어요. 그래서 나중에 IUPAC 명명선이나 다른 과목 서비스를 데이터와 지도 모듈만 더해 열 수 있어요.

## 검사 (게이트)

```bash
node scripts/gate.mjs S4
```

빌드, 단위 테스트, 데이터 검사, 엔진 금지어(엔진에 원소 전용 단어가 없는지), 원소 표기 규칙, 개인정보 규칙(클라이언트에 외부 호출·키·로그인 코드가 없는지)을 한 번에 확인해요.
