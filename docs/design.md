# Science_Metro 디자인 시스템 (design.md v2)

대상: Science_Metro 공통 (Element_Metro MVP부터). 하네스 S2·S3·S4가 읽는다.
근거: uibowl 지하철 레퍼런스 10건 + 운영자 제공 UI 레퍼런스(R11) + 운영자 결정(2026-11-13: 핑크 전부 제거, 메트로 블루, 반응형 3구간).
우선순위: docs/story-service.md > 이 문서 > PRD 원문. 수치 SSOT는 rules.json.
Figma: https://www.figma.com/design/0wVJvRkvqklFbRu6PfTYGK (Design System 페이지)

## 0. 원칙
1. **흰 바탕에 파랑 하나.** 메트로 블루는 누를 수 있는 것, 선택된 것, 진행 중인 것에만 쓴다.
2. **색은 정보다.** 주기율표 칸은 분류 틴트로 칠하고, 노선은 그 위를 달리는 선과 역으로 그린다. UI 바탕(카드, 패널)은 칠하지 않는다.
3. **면으로 나누고 그림자는 쓰지 않는다.** 회색 면, 연한 파랑 면, 1px 테두리, 가는 구분선으로 구역을 나눈다.
4. **작은 글자, 넓은 여백.** 한 화면에 큰 제목은 1개만 둔다.
5. **주기율표가 일러스트다.** 마스코트도, 장식용 타일도 두지 않는다. 노선을 보여 줄 때는 언제나 주기율표 위에 그린다.
6. **AI 티 금지 목록.** 같은 크기 카드 그리드, 카드 위쪽 색 띠, 제목 위 작은 라벨(키커), 정보 없는 반복 줄("기록 없음" ×N), 상자 안 상자. 목록은 카드가 아니라 칩이나 줄로 쌓는다.

적용한 선택 패턴:
- **노선 승차권**: 칸이 회색인 작은 주기율표 위에 그 노선의 모양을 그린다. 노선마다 그림이 달라서 같은 카드 그리드가 되지 않는다. 선택 = 2px 파랑 테두리 + 연한 파랑 바탕. 모바일은 캐러셀, 태블릿·PC는 3열 그리드와 오른쪽 상세 패널.
- **도장 3개**: 완주 / 정확도 90% 이상 / 한 번도 안 틀림. 기존 기록 필드(first_try_correct, total_stations)로 계산한다. 못 받은 도장은 점선 빈 원.
- **묻는 방식 = 작은 노선도**: 5개 모드가 정거장, 그 아래 난도 점 1~3.
- **Element_Metro 둘러보기 탭 3개**: `족·구간 노선 10 | 주기선 6 | 주기율표 학습` (운영자 결정 2026-11-14). 노선 묶음 두 개는 같은 화면에서 바뀌고, 주기율표 학습은 06 화면으로 간다. 06 화면도 같은 탭을 보여 주며 주기율표 학습이 선택된 상태.

## 6-1. 플레이 화면 (Figma `03 플레이`)
- **원자번호 표기 = 문제판.** 원소 기호 왼쪽 아래에 원자번호(₃Li). 묻는 칸이 점선 빈칸이고, **그 빈칸이 곧 입력창**이다.
  - 기호 쓰기: `₃[ L▍ ]` + 아래에 이름(리튬) / 이름 쓰기: `₁₁Na` + 아래 이름 빈칸 / 번호만·완전 혼합: `₉[ ? ]`
  - 빈칸 아래에 무엇을 쓰는지 항상 표시 (기호로 / 이름으로 · Enter / 기호 또는 이름).
- 정답: 빈칸이 초록 실선 + ✓. **별칭으로 맞혀도 칸에는 앱 표기로 바꿔 보여 준다** (소듐 입력 → 칸에 "나트륨 ✓"). 안내 줄: "'소듐'도 정답! 화면에는 '나트륨'으로 보여 줘요." Na·K는 대한화학회 표기(소듐·포타슘)가 아니라 운영자 예외인 나트륨·칼륨을 앱 표기로 쓰므로 "공식 표기"라고 쓰지 않는다 (N2).
- **역 시계**: 도크 맨 위, 이번 역 칸 바로 위 가운데에 흰 알약 `⏱ 00:37.42 | 최고 01:12.05` — 1/100초까지 (운영자 요청). 위 막대의 타이머는 숨긴다(중복).
- **제출은 언제나 Enter** (운영자 요청, PRD 6-3의 "기호는 완성 즉시 자동 이동" 대체): 기호·이름 모두 치는 도중에는 판정하지 않는다. 낸 글자는 이번 역 칸 아래에 `✓ fe` / `✕ fa`로 1.6초 보인다. 데이터: services.json `fields.symbol.input = "submit"` (엔진의 즉시 이동 기능은 남겨 둠).
- **출발 카운트다운** (운영자 요청, PRD 6-3 입력 1 변경): 화면이 열리면 도크 위에 `3 → 2 → 1 → 출발!`(0.8초 간격, 48px, 출발!은 파랑). 시계는 첫 글자가 아니라 **출발!부터** 잰다. 카운트다운 중 입력은 버리지만 키보드는 미리 올라와 있다.
- **이번 역 칸은 늘 가운데**: 도크는 `지난 칸들 | 이번 역 | 다음 칸들` 3칸 격자. 첫 역·종착역 근처에서 한쪽 칸이 없어도 이번 역 칸은 움직이지 않는다.
- 같은 역 2번 오답: 힌트 칩 "힌트: 플○". `모르겠어요 · Esc`는 보조 버튼.
- **배치: 위 = 무대(주기율표 노선도), 아래 = 입력 도크.** 도크는 **원소 칸 3개를 노선으로 꿴 것**: `[지난 원소 칸] ━ [이번 역 큰 원소 칸] ┄ [다음 원소 칸]`. "지난 역/다음 역" 같은 글자 라벨은 쓰지 않는다.
  - 지난 원소 칸: 번호·기호·이름 + 위쪽 분류색 띠 (틀렸으면 빨강 테두리·빨강 기호).
  - **이번 역 큰 원소 칸 = 입력창.** 파랑 3px 테두리, 위쪽 분류색 띠, 번호 / 기호 / 이름 중 묻는 칸이 점선 빈칸이고 그 안에 바로 입력한다. 정답이면 초록 테두리 + ✓.
  - 다음 원소 칸: 번호만, 기호·이름은 흐린 "?", 점선 테두리, 띠는 흐리게 (아직 안 간 역은 번호만, PRD 6-4). 투명도로 흐리게 하지 않는다 (뒤의 선이 비친다).
  - 도크는 화면 폭 전체를 쓴다. 보이는 원소 칸 수: PC 3+1+3, 태블릿 2+1+2, 모바일 1+1+1. 이번 역에서 멀수록 칸이 흐려진다(글자·띠 100% → 60% → 35%). 노선 선은 화면 양 끝까지 이어진다.
  - 지나온 선은 노선색, 앞으로 갈 선은 30~35%.
  - 진행 = 위 막대 바로 아래 **20칸 진행 바**(칸마다 4px, 둥근 끝). 도크 안에는 진행 점을 두지 않는다.
  - 큰 원소 칸의 빈칸은 상자가 아니라 **큰 글자 + 3px 파랑 밑줄**(정답이면 초록).
  - 이번 역 원자 모형은 역 원 지름의 **1.5배**를 넘지 않는다 (옆 역을 가리지 않게). 아래 줄: 무엇을 쓰는지 · 힌트 · `모르겠어요 · Esc`. 도크 바깥 상자는 두지 않는다.
  - 모바일은 도크가 키보드 바로 위에 붙고, 지도를 줄여서라도 도크 전체가 보이게 한다.
- 무대: 칸은 분류 틴트(노선 밖 45%), 지나온 선은 노선색 100%, 앞으로 갈 선은 35%. 역 원 = 통과(노선색 채움 + 흰 기호) / 틀린 역(흰 원 + 빨강 테두리 + 빨강 기호) / 남은 역(흰 원 + 번호) / 이번 역(파랑 원 + 번호).
- **이번 역 = 원자.** 이번 역 원(원자핵) 둘레에 전자 궤도 3개와 전자 2개(⚛). 열차·버스는 쓰지 않는다. 움직임: 전자는 궤도를 돈다, 정답이면 원자가 노선을 따라 다음 역으로 미끄러진다(ease-out 약 400ms). 줄인 모션이면 이동 없이 바로 바뀐다.
- 플레이 중에는 탭·사이드바를 숨긴다. 위 막대: 나가기 · 노선 · 모드 · 진행 · 타이머.
- **바탕과 포인트** (칩스·석가머니·하나원큐 게이미피케이션 화면 참고: 색 바탕 위에 흰 놀이판):
  - 화면 바탕 = `surface`. 무대 = 흰 카드(모서리 16, 모바일 12) + **노선도 종이 점 격자**(24px, 모바일 16px 간격, 점 지름 2px, `text-disabled` 45%).
  - 무대 왼쪽 위 **역 표지판**(태블릿·PC): 진한 판(`text`) 위 흰 글자 `● 기본선 | H → Ca 방면 / 종착역까지 11역`. 모바일은 공간이 없어 두지 않는다.
  - 도크 = **승강장**: 화면 폭 전체의 `primary-tint` 띠 + 위쪽 경계에 파랑 35% 점선(승강장 안전선, 10/6 간격). 이번 역 큰 원소 칸에는 파랑 22% 그림자(아래 12, 흐림 28).
- 메트로 타이핑의 화면 구성은 가져오지 않는다. "아래 도크에 이전/이번/다음"은 R3(슈퍼무브 역 시트)에서 확인한 일반 구조이고, 색·모양은 우리 체계(흰 바탕, 메트로 블루, 표기 빈칸)로만 그린다.

## 6-1-b. 모드 선택 창 (Figma `02-b 모드 선택`)
- 흐름: 노선 승차권 선택 → `○○선 타기` → 모바일 바텀시트 / 태블릿·PC 가운데 창 → `○○선 출발 · 모드`.
- **카드 순서 = 쉬운 것부터** (운영자 결정 2026-11-13): (연습) → 이름 쓰기 → 기호 쓰기 → 번호 쓰기 → 혼합 → 완전 혼합. 처음 열면 이름 쓰기가 선택돼 있다.
  - **번호 쓰기**(예전 '번호만 보고'): 번호를 보고 기호. **역 순서가 매번 섞여 나온다** (modes.json `shuffle: true`). 지도는 노선 순서대로 그리고, 지나온 역만 제자리에 칠한다 (지나온 선 굵게 칠하기는 하지 않음).
  - **연습**: 기호를 보고 이름만 쓴다. 정답 이름이 입력칸 가운데에 연한 글씨(22%)로 깔리고, 친 글자는 그 앞부분에 진하게 겹쳐 그린다 (다른 글자면 빨강). modes.json `ghost: true`. 난도 점 없음. Figma `mode-card` `mode=practice`.
- **모드 = 카드(`mode-card`, 모드 5 × 상태 2).** 카드 위쪽 그림은 작은 원소 칸에서 **어느 칸이 빈칸인지**를 보여 준다 (플레이 화면 큰 원소 칸과 같은 문법): 기호 쓰기 `9/[ ]/플루오린`, 이름 쓰기 `9/F/[ ]`, 번호 쓰기 `9/[ ]/?`, 혼합 = 칸 2장 겹침, 완전 혼합 = 3장 겹침. 그림이 모드마다 달라서 같은 카드 반복이 되지 않는다.
- 카드 아래: 이름 + 난도 점 1~3, 한 줄(무엇 → 무엇 · Enter), 모드별 최고 기록(없으면 "첫 도전"). 선택 = 연한 파랑 + 2px 파랑 테두리 + ✓ 배지.
- PC·태블릿: 가운데 창에 카드 6장을 **3개씩 2줄, 모두 같은 크기** (운영자 요청. 앱 창 880px, 카드 폭 1/3).
- **창 애니메이션 (앱):** 창이 아래에서 떠오르고(0.32초), 카드가 50ms 간격으로 차례로 나타난다. 카드 그림의 빈칸은 **실제로 치는 것처럼** 한 글자씩 써진다. 한글은 두벌식 조합 순서(ㅍ → 프 → 플 → 플ㄹ → 플루…), 치는 동안 파랑 커서가 깜빡인다. 혼합·완전 혼합은 칸을 차례로 친다. 다 친 뒤 약 1.5초 보여 주고 지운 다음 반복. 모드를 바꿔 골라도 애니메이션은 끊기지 않는다. 줄인 모션 설정이면 완성된 글자만 보여 준다.
- 난도 점: 켜진 점은 `primary`(메트로 블루), 꺼진 점은 `border` (운영자 요청). 출발 버튼은 글자 길이만큼(좌우 40px)만 차지하고 가운데 정렬. 모바일: 바텀시트에서 카드(180px)를 옆으로 넘기고, 출발 버튼은 엄지 영역이라 꽉 찬 너비 유지.
- 카드 글자(모드 이름+난도 점, 설명, 기록)는 모두 가운데 정렬.
- **카드 애니메이션 (반복):** 그림이 그 모드가 어떻게 풀리는지 보여 준다. 기호 쓰기·번호만 보고 = 빈칸에 `F`가 채워짐, 이름 쓰기 = 빈칸에 `플루오린`, 혼합 = 겹친 칸 2장 앞뒤 교대, 완전 혼합 = 3장이 돌아가며 앞으로. 1초 → 채움 → 1.2초 → 처음, 전환 0.4초 ease-out. Figma `mode-card`의 `frame=1|2` 변형 + 프로토타입 연결로 구현됨. 줄인 모션이면 멈춘 1장면만.
- 이전 줄 목록형 `mode-option`은 쓰지 않는다 (Design System에 남겨 둠).
- 혼합 모드 기록은 단일 모드와 따로 저장된다는 안내를 창 위쪽에 둔다.

## 6-2. 패널 구획
상세 패널은 영역을 눈으로 나눈다: 지도+범례 = 회색 면 / 도장+최고 기록 = "내 기록" 테두리 상자 / 구분선 / 묻는 방식+출발.

**"내 기록" 상자** (알약 칩 쓰지 않음):
- 최고 기록: 두 칸(최고 기록 | 정확도), 작은 라벨 + 큰 숫자(title-m), 사이 1px 구분선 (R27).
- **도장 = 작은 노선도** (R13·R17): 완주(깃발) — 정확도 90%(과녁) — 무오답(방패 체크)을 정거장처럼 선으로 잇는다. 받은 도장 = 파랑 원 + 흰 아이콘, 못 받은 도장 = 점선 빈 원 + 흐린 아이콘. 받은 도장까지의 선은 파랑, 나머지는 회색.

## 6-3. 기록 페이지 (Figma `04 기록`) · 랭킹 등록 (`05 랭킹에 올리기`)
- 모바일: `주간 랭킹 | 내 기록` 탭. 태블릿·PC: 왼쪽 랭킹, 오른쪽 "내 기록(이 기기)" 패널.
- 랭킹 순서: 노선·모드 선택(드롭다운) → `전체 | 우리 학교` → 이번 주 기간과 초기화 안내 → `이번 주 순위` 제목 + **'내 주변만' 스위치**(켜면 단상을 숨기고 내 위아래 2명만) → **1~3위 단상** → **내 순위 요약 상자** → 4위부터 목록.
  - 단상: 2·1·3 순서, 카드 아래 단 높이 1위 > 2위 > 3위. 카드 맨 위에 **메달**(메트로 블루 리본 + 금 #C9A227 / 은 #9AA5B4 / 동 #B5774A 원 + 순위 숫자, 변수 `medal/*`). 1위 카드는 연한 파랑 바탕 + 파랑 테두리 + 단 파랑, 2·3위는 회색 단. 카드에는 닉네임·학교·시간·정확도.
  - 내 순위 요약: 큰 숫자 "7위" + "상위 6%" 배지 + 백분위 막대, 아래 `전체 7위 · 128명 중 | 우리 학교 3위 · 31명 중`. 기록을 올린 적 없으면 상자 대신 '랭킹에 올리기' 안내.
  - 목록: 순위 숫자를 크게(title-l), 숫자는 흐리게. 내 줄은 파랑 테두리 + "나" 배지.
  - 모바일 = 줄형(순위 · 닉네임/학교 · 시간/정확도). 태블릿·PC = 표형(순위 / 닉네임 / 학교 / 시간 / 정확도, 시간·정확도 오른쪽 정렬).
  - 요약 상자와 내 줄이 둘 다 화면 밖이면 하단 탭 위에 "내 순위" 줄을 고정하고 바로 위 순위와의 차이를 적는다 ("6위와 2초 차이").
  - 참고: 골프존(내 순위 요약), 무디·당근(큰 순위 숫자 목록), 비즈 앤 타운(내 주변 보기), KBO STATS(표형).
- 트로피·왕관은 쓰지 않는다. 메달은 1~3위 단상에만.
- 내 기록 패널: 모드별 최고 기록(없으면 "첫 도전"), 자주 틀린 원소 칸(빨강 8% 바탕 + 빨강 테두리 + 틀린 횟수).
- 랭킹 등록: 이번 판 요약 → 학교 검색(NEIS, 결과 목록에서 선택) → 닉네임(2~10자, 실명 금지 안내, 글자 수) → 공개 확인 체크(필수) → `다음에` / `랭킹에 올리기`. 모바일 바텀시트, PC 가운데 창(520px).
- 백엔드 규격: docs/backend.md.

## 6-4. 주기율표 학습 페이지 (Figma `06 주기율표` · `06-b 원소 상세`)
- 메뉴 위치: 주기율표는 Science_Metro 전체 메뉴가 아니라 **Element_Metro 안**에 둔다 (다른 서비스가 열리면 그 서비스는 자기 학습 페이지를 가진다).
  - 전체 메뉴(하단 탭·레일·사이드바)는 홈 · 노선 · 내 기록 3개.
  - PC 사이드바 아래에 **서비스 목록**: `Element_Metro 운행 중` → 하위 `노선도` · `주기율표 학습`. 서비스가 늘면 이 목록에 줄이 추가된다.
  - 모든 크기: 02 노선 선택과 06 주기율표 학습 위쪽의 같은 탭(`족·구간 노선 | 주기선 | 주기율표 학습`)으로 오간다. 예전의 `주기율표 학습 ›` 링크와 `‹ Element_Metro` 뒤로 가기는 없앴다.
- 페이지: 제목 + 설명 + 검색(이름·기호) → 분류 칩(전체 + 10개 분류, 누르면 그 분류만 진하게) → 주기율표 118칸(분류 틴트, 번호·기호·이름). f구역은 12px 띄운다.
  - 칸 크기: PC 59×66, 태블릿 56×56, 모바일 40×44(이름 없이 번호·기호, 표 가로 스크롤 + 오른쪽 흐림 + "옆으로 밀어서 전체 보기"). 긴 이름(5자 이상)은 말줄임.
- **원소 상세 팝업** (PC·태블릿 가운데 창 1040 / 1000px, 모바일 바텀시트):
  - 왼쪽 = 원소 기호 표현: 분류 틴트 판 위에 원자번호, 분류·주기·족 칩, 큰 기호(display), 이름, 영어 이름·원자량, **보어 모형**(핵 = 분류색 + "11+", 껍질 원, 전자 점. 바깥 껍질 전자는 파랑) + "껍질별 전자 2 · 8 · 1".
  - 오른쪽: 이름(대한화학회 표기 / 이 앱 표기 — Na·K처럼 둘이 다를 때만 두 줄, 같으면 한 줄 / 예전 이름이 있으면 "입력해도 정답" / 영어 / 한자 / 기호 유래) → 전자 배치(표기 + 줄인 표기 + **오비탈 상자 그림** ↑↓) → 성질 6칸(원자량, 밀도, 상온 상태, 녹는점, 끓는점, 전기 음성도) → 발견(연도·사람·나라 + 두 문장).
  - 아래 띠: "이 역을 지나는 노선" 노선 칩 + `기본선으로 출발 →`. 학습에서 바로 플레이로 이어진다.
  - 모바일 시트: 왼쪽 판이 가로 판(기호 + 보어 모형)으로 바뀌고 나머지는 세로로 쌓는다.
- 데이터 (구현됨 2026-11-14): `app/data/elements-detail.json` — 원자량(방사성은 [가장 안정한 동위원소]), 밀도(기체는 g/L), 녹는점·끓는점(1기압 °C), 전기 음성도, 상온 상태, 발견 연도·발견자, 중국어 이름, 우리말 한자 이름(水素 등 있는 원소만), 기호 유래(라틴어 등), 대한화학회 표기가 앱 표기와 다른 경우(Na 소듐, K 포타슘). 모르는 값은 null → 화면에 "—". **`reviewed: false` = 교사 검수 전**이고 팝업 아래에 그렇게 적는다.
  - 전자 배치·껍질별 전자 수는 계산한다 (`src/map/electrons.ts`: 쌓음 원리 + Cr·Cu·Nb·Mo·Ru·Rh·Pd·Ag·La·Ce·Gd·Pt·Au·Ac·Th·Pa·U·Np·Cm·Lr 예외). 104번 이후는 예측값이라고 표시.
  - 오비탈 상자: 20번까지는 1s부터 전부, 그 뒤는 비활성 기체 뒤 부분만.
- 앱 주소: `/element/table`, 원소를 열면 `/element/table?z=11` (공유 가능). 검색은 이름·기호·영어 이름·번호·예전 이름 모두 찾고, Enter로 첫 결과를 연다.

## 7. 접근성 (셀 수 있는 규칙)
1. 글자 대비 4.5:1 이상 (24px 이상 또는 18.66px Bold 이상은 3:1). `text-disabled`는 비활성 표시에만 쓴다.
2. 터치 영역 44×44 이상 (주기율표 칸은 보기 전용이라 예외).
3. 상태를 색 하나로만 보여 주지 않는다 (2-4 표).
4. `prefers-reduced-motion`이면 깜빡임·흔들림을 끈다.
5. 입력창: `autocapitalize="off" autocomplete="off" autocorrect="off" spellcheck="false"`.
