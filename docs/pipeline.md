# 파이프라인 (R3)

입력 단위: 서비스 1개 (docs/harness-purpose.md). story-work 1~9단계를 5단계로 묶는다.

| 단계 | story-work | 도구 | 입력 | 출력 | 단계 끝 게이트 |
|---|---|---|---|---|---|
| S1 리서치·설계 | 1·2·3 | uibowl MCP | prd.md, story-service.md | 레퍼런스 모음, 반영 목록, 화면 설계서 | 기계: 설계서에 PRD 5장 MVP 화면이 빠짐없이 있음 |
| S2 키스크린 | 4·5 | Figma MCP | 화면 설계서 | Figma 키스크린 3장: 플레이·결과·노선 선택, 각 390×844 | **사람: 시안 확정** |
| S3 디자인 시스템·화면 | 6·7 | Figma MCP | 확정 시안 | 토큰, 컴포넌트, 전체 화면 | 기계: 가이드 위반 검사 |
| S4 개발 | 8 | 코딩 에이전트 | 토큰, 화면, PRD 8장 데이터 모델 | 정적 웹앱 코드, data/ JSON | 기계: 빌드·단위 테스트·데이터 검사 |
| S5 검증·배포 | 9 | 브라우저, Vercel | 앱 | 체크리스트 결과, 배포 URL | 기계 + 사람 체크 (harness-purpose 완료 기준) |

## 되돌아가는 지점
| 실패 | 복귀 |
|---|---|
| S2 사람 반려 | S2 (사유가 "설계 문제"면 S1) |
| S3 가이드 위반 | S3 |
| S4 빌드·테스트·데이터 검사 실패 | S4 |
| S5 체크 실패 — 동작 문제 | S4 |
| S5 체크 실패 — 화면 문제 | S3 |
| 같은 단계 3회 연속 실패 | 멈추고 사람에게 넘김 |
